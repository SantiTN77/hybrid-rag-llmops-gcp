## 1. Why Firestore Vector Search Over Vertex AI Vector Search Endpoints
Meridian standardized on GCP Cloud Firestore Native mode with built-in Vector Search (`find_nearest`) for enterprise RAG corpora under 2 million chunks. Unlike Vertex AI Vector Search Index Endpoints—which require always-on deployed nodes costing approximately $75–$140/month per node even at zero traffic—Firestore Vector Search is 100% serverless with **$0.00 idle cost**. Storage is billed at $0.18/GiB/month and reads at $0.06 per 100,000 document reads.

## 2. Database Isolation & Collection Schema
Production RAG workloads MUST use a dedicated named Firestore Native database (`hybrid-rag-db`) in `us-central1` rather than colliding with the project's `(default)` database.
The primary chunk collection is `rag_chunks`, where each document contains:
- `doc_id` (string): Stable identifier of the source technical document.
- `title` (string): Human-readable document title.
- `section` (string): Markdown H2 section heading.
- `chunk_index` (integer): Zero-based chunk ordinal within the document.
- `content` (string): Raw text of the chunk (target 220–320 words, 40-word overlap).
- `tokens` (array<string>): Lowercased, stopword-filtered lexical tokens for BM25 keyword scoring.
- `embedding` (`Vector`): Dense float vector generated by Vertex AI `gemini-embedding-001` (or `text-embedding-005`) stored via `google.cloud.firestore_v1.vector.Vector`.

## 3. Vector Index Configuration & Distance Measures
Firestore requires a single-field or composite vector index on `embedding` before `find_nearest` queries can execute. For semantic text retrieval, Meridian mandates:
- **Distance Measure**: `COSINE` (distance range `0.0` identical to `2.0` opposite; similarity computed as `1.0 - distance`).
- **Index Type**: `FLAT` index configured via Terraform `google_firestore_index` with `query_scope = "COLLECTION"` and `vector_config.dimension` matching the exact embedding dimensionality (e.g., `768` when `output_dimensionality = 768` is enforced).
- Note: Firestore vector indexes support up to **2048 dimensions** maximum. When using `gemini-embedding-001` (default 3072 dims), pipelines MUST explicitly set `output_dimensionality=768` (Matryoshka Representation Learning) so embeddings stay well under Firestore's 2048-dimension limit while preserving >98% retrieval recall and cutting storage by 75%.

## 4. Hybrid Retrieval & Reciprocal Rank Fusion (RRF)
Pure dense vector search frequently misses exact error codes, IAM role strings (e.g., `roles/run.invoker`), and version numbers. Meridian's RAG API combines:
1. **Dense Vector Retrieval**: Firestore `find_nearest(vector_field="embedding", distance_measure=DistanceMeasure.COSINE, limit=top_k_dense)`.
2. **Sparse Lexical Retrieval (BM25)**: Okapi BM25 (`k1 = 1.5`, `b = 0.75`) over the indexed `tokens` and content fields.
3. **Reciprocal Rank Fusion (RRF)**: Combines dense rank `r_v` and lexical rank `r_l` using `score = w_v / (k + r_v) + w_l / (k + r_l)` with default smoothing constant `k = 60`, `w_v = 0.60`, and `w_l = 0.40`.
